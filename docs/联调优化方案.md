### P1 — 影响核心体验

#### 4. 首页数据全部硬编码

- **文件**：`components/HomeContent.ets` (L13-20)
- **硬编码项**：
  | 变量 | 硬编码值 | 应来源 |
  |------|---------|--------|
  | `userName` | `'小明'` | 用户信息（登录后获取） |
  | `streakDays` | `12` | 从 `daily_task` 表聚合计算 |
  | `todayProgress` | `75` | 从今日任务完成度计算 |
  | `newWordsCount` | `15` | 从当前关卡词表获取 |
  | 关卡入口 `lessonId` | `4` | 从 `LearningState` 获取当前进度 |
- **影响**：首页展示的数据与真实学习进度完全脱节

#### 5. DictContent 组件过于庞大（1,973 行）

- **文件**：`components/DictContent.ets`
- **现状**：单文件承载了全部词典功能：
  - 搜索输入 + 搜索历史
  - SSE 流式请求 + 逐字渲染
  - 搜索结果展示
  - AI 详细解析
  - 收藏夹列表 + 详情页
  - 划词翻译
  - 浏览历史
- **状态变量**：超过 30 个 `@State`
- **影响**：可维护性差，联调时修改一处可能影响其他功能

#### 6. 生词本数据存储不一致

- **文件**：`services/VocabularyService.ets` vs `services/DatabaseService.ets`
- **现状**：
  - `DatabaseService` 定义了 `wordbook` RDB 表并有 `addToWordbook()` 方法
  - `VocabularyService` 实际使用 `Preferences`（JSON 序列化）存储生词
  - 两套存储互不关联
- **影响**：数据可能不同步，`DatabaseService.getWordsToReview()` 返回的数据与 `VocabularyService` 不一致

### P2 — 工程质量

#### 7. 主题系统三套方案并存

- **涉及文件**：`utils/Constants.ets`、`utils/ThemeManager.ets`、各组件
- **三套方案**：
  1. `ThemeColors` 类 — 通过构造函数传入 `isDark`，实例化使用
  2. `AppColors` / `COLORS` — 静态 getter，依赖全局 `runtimeIsDarkMode` 变量
  3. `ThemeManager` 实例 — 通过 `themeManager.bgBody` 等 getter 获取
- **使用现状**（混乱）：
  - `HomeContent` 使用 `COLORS.TEXT_PRIMARY`
  - `Index` 使用 `DarkTheme.BG_BODY` / `LightTheme.BG_BODY` 三元表达式
  - `DictContent` 混合使用 `COLORS` 和 `themeManager.isDark()` 三元
- **建议**：统一为一种方案，推荐 `themeManager` 单例 getter

#### 8. 临时音频文件无清理机制

- **文件**：`services/AudioService.ets` (L155-161)
- **现状**：每次 TTS 播放创建临时文件 `temp_audio_${Date.now()}.mp3`，从不删除
- **影响**：长期使用会在 `cacheDir` 下积累大量垃圾文件
- **建议**：播放完成后删除临时文件，或实现 LRU 缓存

#### 9. HTTP 客户端实例复用可能有并发风险

- **文件**：`services/ApiService.ets` (L71)
- **现状**：`this.httpClient = http.createHttp()` 在构造函数中创建一次，所有请求共用
- **潜在问题**：鸿蒙 `http.createHttp()` 返回的实例是否线程安全未确认
- **建议**：改为每次请求创建独立 `httpClient`，或确认官方文档的并发安全性

### P3 — 技术债务

#### 10. ApiService JSON 解析代码冗长

- **文件**：`services/ApiService.ets` (L178-350, ~170 行)
- **现状**：`searchDict()` 方法手动逐字段解析 JSON，代码量极大
- **示例**：
  ```typescript
  entry.hangul = item['hangul'] as string || '';
  entry.romanization = item['romanization'] as string || '';
  entry.pos = item['pos'] as string || '';
  // ... 数十行类似代码
  ```
- **建议**：封装通用解析工具方法，减少重复代码

#### 11. LessonPage 存在 Mock 数据回退

- **文件**：`pages/LessonPage.ets` (L192-222)
- **现状**：API 加载失败时回退到硬编码的 2 个词（안녕、감사합니다）
- **问题**：Mock 数据仅 2 个词，练习题生成依赖至少 4 个词的错误选项池
- **建议**：上线前移除 Mock 回退，或使用更完整的离线词库

#### 12. StudyContent 关卡数计算未与后端对齐

- **文件**：`components/StudyContent.ets` (L44-47) + `utils/Constants.ets` (L41-44)
- **现状**：`TOPIK_LEVELS` 中关卡数硬编码（78/189/61），基于 `词数 / 20` 计算
- **问题**：如果用户修改了"每关单词数"设置（`LessonPage` 支持），关卡总数不变
- **建议**：关卡数应由后端 API 动态返回，或根据 `wordsPerLesson` 设置动态计算

#### 13. PreferencesService 使用 object literal 创建默认值

- **文件**：`services/PreferencesService.ets` (L9-21)
- **现状**：`DEFAULT_USER_SETTINGS` 和 `DEFAULT_LEARNING_STATE` 使用 `{ ... }` 创建
- **问题**：ArkTS 严格模式下通过 object literal 创建 class/interface 实例存在风险
- **建议**：改为 `new UserSettings()` + 手动赋值
