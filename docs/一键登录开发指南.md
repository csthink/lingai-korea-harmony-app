# 阿里云号码认证（一键登录）接入开发指南

本文档整理了接入阿里云一键登录功能的完整流程，包括华为后台配置、阿里云控制台配置及本地开发设置。

> 最后更新：2026-03-22

## 一、华为 AppGallery Connect 配置（获取 App ID）

> **前置条件**：必须注册华为开发者账号并完成实名认证。

1.  **登录控制台**：
    访问 [华为 AppGallery Connect](https://developer.huawei.com/consumer/cn/service/josp/agc/index.html)。
2.  **创建应用**：
    *   点击 **"我的应用"** -> **"新建"**。
    *   **应用名称**：填写项目名称（如 LingAI）。
    *   **包名**：必须与本地 `AppScope/app.json5` 中的 `bundleName` 一致（本项目为 `com.lingai.app`）。
    *   **应用分类**：按需填写。
    *   **注意**：创建后**无需**上传安装包，也**无需**提交审核发布。
3.  **获取 App ID**：
    *   创建成功后，进入 **"应用信息"** 页面。
    *   复制 **"App ID"** 字段（本项目：`6917597519602711463`）。此 ID 将用于阿里云后台配置。

## 二、阿里云号码认证控制台配置（获取密钥）

1.  **登录控制台**：
    访问 [阿里云号码认证服务控制台](https://dypns.console.aliyun.com/)。
2.  **添加认证方案**：
    *   点击 **"新增号码认证方案"**。
    *   **操作系统**：选择 **HarmonyOS**。
    *   **包名**：填写 `com.lingai.app`（需与华为后台一致）。
    *   **AppId**：填写上一步从华为后台获取的 App ID。
    *   **包签名**（SHA256 指纹，去冒号格式）：
        *   通过以下命令从 DevEco 生成的证书中提取：
            ```bash
            # 证书文件在 ~/.ohos/config/ 下，名称含项目名
            # .cer 包含证书链（3 个证书），取最后一个（end-entity）
            python3 -c "
            import re, subprocess
            with open('证书路径.cer') as f:
                content = f.read()
            certs = re.findall(r'(-----BEGIN CERTIFICATE-----.*?-----END CERTIFICATE-----)', content, re.DOTALL)
            p = subprocess.run(['openssl', 'x509', '-noout', '-fingerprint', '-sha256'], input=certs[-1], capture_output=True, text=True)
            print(p.stdout.strip().split('=')[1].replace(':', ''))
            "
            ```
        *   当前 Debug 证书指纹：`A432B77B3C083D60972CD8EE792500FFA55AC4C1B6766C7A0EA69E7319434F14`
        *   **Release 证书**：需使用 release 签名材料重新提取。
    > ⚠️ 包签名必须与 DevEco **当前使用的签名配置**一致，否则会报 `600017`（密钥/方案不匹配）。
    > 在 DevEco 中重新拉取 profile 后签名会变化，务必同步更新阿里云控制台。
3.  **获取 Secret Key**：
    *   方案创建成功后，在列表页查看并复制 **密钥 (Secret Key)**。

## 三、本地项目配置

1.  **配置依赖**：
    *   确保 `entry/libs/China_Ali_PNVS.har` 存在。
    *   执行 `ohpm install` 或在 IDE 中点击 Sync。
2.  **配置密钥**：
    *   `Constants.ets` 中的 `PNVS_AUTH_SECRET` 仅保留占位值（`__PNVS_SECRET_PLACEHOLDER__`），**不提交真实密钥**。
    *   本地调试时有两种注入方式：
        *   **方式一**（推荐）：直接修改 `Constants.ets` 中的占位值为真实密钥，但提交前还原。
        *   **方式二**：在代码中调用 `OneClickAuthService.getInstance().overrideSecret('真实密钥')` 注入。
3.  **签名配置**：
    *   在 DevEco Studio 中：**File → Project Structure → Signing Configs**，勾选自动签名。
    *   确认登录的华为账号对应 AGC AppId `6917597519602711463`。
    *   DevEco 会自动拉取签名材料并更新 `build-profile.json5`。
4.  **权限声明**：
    `module.json5` 中需声明以下权限：
    | 权限 | 用途 |
    |------|------|
    | `ohos.permission.INTERNET` | 网络请求 |
    | `ohos.permission.GET_NETWORK_INFO` | 判断网络环境 |
    | `ohos.permission.SET_NETWORK_INFO` | 一键登录时切换蜂窝数据通道 |
5.  **真机调试**：
    *   使用 DevEco Studio 连接真机。
    *   确保手机插入 SIM 卡并开启蜂窝数据网络。
    *   运行 App 进行测试。

## 五、错误码、状态机与处理策略

为了保证流程幂等和避免并发冲突，本 SDK 适配层实现了一个内部状态机：`IDLE` -> `AUTH_PAGE` -> `PROTOCOL_DIALOG` -> `SUBMITTING` -> `SUCCESS` / `FAILED`。

**事件语义与状态转移映射：**

| SDK Code / 事件 | 用户动作 | 语义映射 | 状态转移 | Promise 处理 |
| :--- | :--- | :--- | :--- | :--- |
| `700000` / `.authpage.return` | 授权页点击返回 | `AUTH_PAGE_CLOSED` | `AUTH_PAGE` -> `FAILED` | 注入错误并 `reject` (降级排查短信) |
| `.dialog.cancel` / `700004` | 协议弹窗点击取消 | `PROTOCOL_CANCELLED` | `PROTOCOL_DIALOG` -> `AUTH_PAGE` | **忽略错误，保持 pending** |
| `600000` | 成功获取 Token | `SUCCESS` | `*` -> `SUCCESS` | 提取并 `resolve` |
| `600001` | 授权页唤起成功 | N/A | `IDLE` -> `AUTH_PAGE` | 记录页面可见状态 |
| `.dialog.agree` / `600006` | 同意协议 / 开始取号 | `SUBMITTING` | `PROTOCOL_DIALOG`/`AUTH_PAGE` -> `SUBMITTING` | 无 |
| UI 点击相关码 (如 `700002`) | 纯 UI 埋点动作 | N/A | 无变化 | 纯忽略，不切断流程 |
| 其他未识别 Code | 网络、SDK 或终端异常 | `FAILED`（含内部转储如 `NETWORK_ERROR` 等） | `*` -> `FAILED` | 注入错误并 `reject` |

### 5.1 详细错误分类（部分枚举）

| 错误码枚举 | 触发原因 | 处理 |
|--------|------|------|
| `CARRIER_ERROR` (600004/10/11) | 运营商鉴权失败 | 降级短信登录 |
| `CONFIG_MISMATCH` (600016/17/20/21) | 密钥/方案/签名配置错误 | 检查控制台配置 |
| `NETWORK_ERROR` (600005/07/08/13-15/28) | 网络不稳定/无网络 | 降级短信登录 |
| `SDK_NOT_AVAILABLE` (600024/25) | 终端环境不支持 | 降级短信登录 |
| `RATE_LIMIT` | 被阿里云流控策略拦截 | 等待 8 秒后重试，可降级短信登录 |
| `TIMEOUT` | 全局 5 秒超时保护触发 | 降级短信登录 |

**并发策略与防重复执行**：
内部通过单调递增的 `attemptId`，确保旧的拉起动作如果未结束就在新拉起产生时，立刻转入 `SUPERSEDED` 而安全丢弃。日志中强制记录 `[OneClick] attemptId=... state=... semantic=... code=... traceId=N/A` 用于精确定位回溯。
同时，每次请求 `/api/app/auth/login/one-click` 时，会在请求头中携带 `X-Client-Attempt-Id`，以便于实现了端到端的会话日志追踪。

## 六、常见问题

*   **错误码 600017**：密钥/方案不匹配。最常见原因：
    1.  DevEco 重新拉取 profile 后签名变化，但未同步更新阿里云控制台的包签名。
    2.  `PNVS_AUTH_SECRET` 与阿里云方案不对应（方案更换后旧密钥失效）。
    3.  `bundleName` 与阿里云方案中配置的不一致。
*   **错误码 600024**：终端环境检查失败。App ID、包名或签名与阿里云后台配置不一致。
*   **错误码 600010**：Token 获取失败。请检查密钥是否正确，或套餐包余量是否充足。
*   **卸载重装后提示“设备数量超过限制”**：
    1.  早期客户端使用本地持久化 UUID 作为 `deviceId`，卸载 App 会清空本地存储，重装后会生成新的 `deviceId`。
    2.  服务端会把新 `deviceId` 视为新设备；如果同一台手机历史上已经留下多条记录，就可能命中 `3005 - 设备数量超过限制`。
    3.  2026-03-22 起客户端已优先使用 HarmonyOS `ODID` 作为稳定设备标识，`Unified` 也会在一键登录时自动合并同机重装遗留记录。
    4.  如果联调环境仍残留旧 UUID 设备行，可在 `Unified` 的 `t_user_device` 表中清理 `status=0` 且 `deleted_at IS NULL` 的历史记录。
*   **本地包名被占用**：如果华为后台提示 `com.lingai.app` 被占用，需先修改本地 `AppScope/app.json5` 中的 `bundleName`，再重新申请。
*   **Resource Pack Error**：提示 `$string:xxx_permission_reason` 未定义。在 `entry/src/main/resources/base/element/string.json` 中添加相应键值对。
*   **ArkTS Compiler Error (no-any-unknown)**：使用显式类型转换（如 `as Record<string, Object>`）。SDK 回调中忽略参数使用 `_` 前缀。

## 七、开发注意事项

1.  **密钥安全**：`Constants.ets` 中的 `PNVS_AUTH_SECRET` 代码仓库中应保留占位符，**禁止提交真实密钥**。`overrideSecret()` 方式注入最安全。
2.  **签名同步**：每次在 DevEco 重新拉取 profile 后，必须将新的 SHA256 指纹更新到阿里云控制台。
3.  **真机调试**：一键登录强依赖蜂窝网络。模拟器无法测试，必须使用插卡的真机，并关闭 Wi-Fi 或保证移动数据优先。
4.  **日志脱敏**：密钥仅输出长度和前后 4 位摘要（`secretSummary()`），不输出完整值。
5.  **权限声明**：`module.json5` 中申请的敏感权限必须在 `string.json` 中提供描述，否则会导致编译失败。
6.  **用户信息展示**：`ProfileContent` 优先展示手机号，其次是昵称。若获取用户信息失败，会自动回滚到未登录状态。
7.  **API 调用**：`getCurrentUserInfo` 使用直连 Unified Service 的方式（不走 `BIZ_API_PREFIX`），避免 404 错误。
8.  **设备标识策略**：`ApiService` 现已优先使用 HarmonyOS `ODID` 作为 `deviceId`，只有系统未提供 `ODID` 时才回退到本地 UUID。联调时不要手动改回随机 UUID，否则会重新引入卸载重装后的设备漂移问题。

## 八、安全最佳实践 (Security Best Practices)

### 1. 密钥管理 (Secret Management)
为了防止密钥泄露，本项目采取了以下措施：
- **占位符**：`Constants.ets` 中的 `PNVS_AUTH_SECRET` 已替换为 `__PNVS_SECRET_PLACEHOLDER__`，禁止提交真实密钥。
- **本地注入**：开发环境请在 `entry/src/main/ets/local/Secret.dev.ets` 中配置真实密钥（该文件已加入 `.gitignore`）。App 启动时，`EntryAbility` 会自动读取并注入该密钥。

### 2. 日志脱敏 (Log Sanitization)
为了防止 SDK 内部日志泄露敏感信息（如 `setAuthSDKInfo` 中的密钥），本项目集成了全局 **Console Interceptor**：
- **原理**：在 `EntryAbility` 启动时拦截全局 `console` 对象。
- **规则**：自动屏蔽包含 `setAuthSDKInfo`、`secretInfo`、`accessCode`、`token` 等关键词的日志。
- **位置**：`entry/src/main/ets/utils/ConsoleInterceptor.ts`。

请确保在调试时不要尝试绕过此拦截器打印真实密钥。
